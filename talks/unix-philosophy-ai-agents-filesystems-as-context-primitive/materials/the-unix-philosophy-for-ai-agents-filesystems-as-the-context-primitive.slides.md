## Slide 4 — Shared state needs boundaries
**Text.** Shared state needs boundaries / Multi-agent workflows need to share state, but not all state should be shared in the same way. / Agent A → Agent B → Agent C → Agent D → Agent E (with dotted feedback arcs A↔D style) / STATE TYPE | WHO CAN ACCESS? | HOW LONG? | WHO CAN WRITE? / Private working state (plan, scratchpad) | one agent | task | the creator / Shared coordination state (intermediate output, artifact) | workflow agents | conversation | coordinated writers / TOO ISOLATED — Agents cannot coordinate, handoffs lose context, work is repeated. / TOO EXPOSED — Private state leaks, and the wrong agents can read or change shared state. / Different state needs different access, lifetime, and write rules / Bloomberg

## Slide 6 — Agents work one layer above the filesystem
**Text.** Agents work one layer above the filesystem / TOO LOW — FUSE AND POSIX / Byte-level access: open, seek, read(offset, length). Every call is a round trip. / Efficient locally, costly remotely: Fine against a local disk. Expensive across a network, and the agent gains nothing from the extra precision. / Is this FUSE? FUSE specifies byte-level access to a local mount. / THE LAYER WE WANT / The harnesses already work here: Their tools are not filesystem calls, and none of them operate on byte offsets. / Operations execute at the source: Today a source is mounted through to the client and treated as an ordinary filesystem, which makes transfer, search and write-back inefficient. / Is this File Uploads? File Uploads declares user-selected file inputs. Its charter puts server-side content with Resources. / TOO HIGH — OPERATIONS MODELLED PER SOURCE / Large surface area: Standardising operations at the level each source already thinks in means every implementer builds a lot and keeps little flexibility. / Where this sits today: MCP resources carry read and list. Anything richer arrives as per-server tools, so the rich operations are never shared. / Is this HTTP again? Where HTTP already carries the semantics, adopt them rather than specifying parallel ones. / Which layer should the protocol specify? That is what the working group exists to answer. / Bloomberg
**Shows.** Three side-by-side panels (too low/FUSE, the desired layer, too high/per-source) each with two explanatory cards and a small FAQ-style footnote box addressing a likely audience objection (Is this FUSE? / Is this File Uploads? / Is this HTTP again?), framing the talk's core architectural argument about where to pitch the new abstraction.

## Slide 7 — What we borrow from Unix
**Text.** What we borrow from Unix / Unix is broad. We borrow one pattern, because models are already trained on these operations and the harnesses converged on them independently. / CLASSIC UNIX PATTERN — grep | sort | uniq — small tools connected through a simple convention / Do one thing well: grep searches. sort orders. Neither tool knows the other. / Discovery precedes reading: ls names what is there. grep looks inside it. / Outputs become inputs: grep ERROR app.log | sort | uniq -c / Text streams form a common interface: A program reads a byte stream, without the producer's internals. / ADAPT → / OUR AGENT ADAPTATION — retrieve → /thread/source.md → analyse → /task/findings.json → synthesise — steps compose through stable, named handoffs / Small operations: list(path), read(path), write(path, data), search(path, query), discover(path). / Discovery and search run at the source: Matching happens where the content already is, so only the results travel. / Operations compose over a path: discover /thread, then search /thread, then read the matches. One vocabulary against any mount. / Stable, path-addressed handoffs: retrieve writes /thread/source.md. analyse reads that path. Either step can be replaced, and models, tools and people read the same file. / Borrow the goal: composability. Adapt the mechanism: paths and file operations. / Bloomberg
**Shows.** A side-by-side comparison: a "classic Unix pattern" panel showing grep|sort|uniq piped together with four numbered Unix principles, and an "our agent adaptation" panel showing a retrieve→analyse→synthesise pipeline connected via named file paths, with the same four principles restated in agent terms; an orange "ADAPT" arrow links the two panels.
