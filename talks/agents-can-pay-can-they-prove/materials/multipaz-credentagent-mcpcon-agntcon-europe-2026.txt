WHAT THIS IS BUILT ON
Open standards did the hard part
We stand on the shoulders of giants: the standards bodies did the hard part, the wallet implements it, and 
CredentAgent only parses and verifies.
Credential formats
ISO 18013-5/7 mdoc SD-JWT
ISO and IETF defined the formats. The wallet holds them; we 
parse and verify — we define nothing new.
Request & presentation
OpenID4VP DCQL W3C Digital Credentials API 
OpenID & W3C defined the ask. DCQL expresses the query; 
the DC API carries it natively.
Device binding
WebAuthn / FIDO2 FIDO PXP Secure element 
FIDO & W3C bound the device. Origin-bound; cross-device 
when the desktop asks and the phone answers.
Agentic commerce & settlement
AP2 DPC x402
The one layer still being written. — MCP moves the agent, 
ACP/UCP the cart, AP2 authorizes, x402 settles. 
MULTIPAZ  implements these open standards — donated by Google, improved in the open (Kotlin Multiplatform, one 
codebase for iOS + Android).
The giants wrote the specs; the wallet stands on them, and so do we.

--- slide 16 ---
CREDENTAGENT · 2 of 2
Gate any credential you deﬁne
age, payment, membership are just built-ins — define and query any doctype the same way.
// the built-ins are just pre-defined credentials — 
// query ANY doctype the same way: 
const license = defineCredential({
  id: "professional_license", 
  request: dcql({ docType: "org.example.license.1", 
                claims: ["license_active"] }), 
  verify: (c) => c.license_active === true, 
  effect: gate(),    // block until proven 
  ui: { label: "Professional license", action: "Verify" }, 
});
 
credentagent.requirements(order, [ 
  required(license),    // your credential 
  required(age.over(21)),   // + the built-ins 
  required(payment.in("usd")), 
]);
Define once
id · request · verify · effect · ui. No registration 
step.

--- slide 30 ---
HONEST STATUS
What binds cryptographically —
and what does not
Real today
• WebAuthn — origin-bound, replay-protected 
• OpenID4VP — •Encrypted responses, decrypted and parsed 
server-side
• ISO mdoc parsing, cross-device via PXP / caBLE
• Enforcement server-side on the completion path
Not yet
• No issuer or device-signature trust anchor
• A self-crafted mdoc would pass today
• AP2-shaped mandate is dev-signed, not key-signed
• Issuer-verified mdoc via Multipaz is the next line
• Agent round trip is poll-based; MRTR is roadmap
trust_level: "presence-only-demo"  —  a flow demo, not a safety control.
