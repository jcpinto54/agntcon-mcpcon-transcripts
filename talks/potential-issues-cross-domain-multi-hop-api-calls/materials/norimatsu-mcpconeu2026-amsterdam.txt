Token Types That Can Prevent Information Leaks
Handle/Reference type token:
• The token does not include any information.
• Its intended receiver can only extract them by token introspection*1.
  
Signed and Encrypted JWT-formatted Assertion/Self-contained type token:
• The token includes all Information.
• The token is signed and encrypted by its issuer*2.
• The token can only be decrypted by its intended receiver*2. 
*1: OAuth 2.0 Token Introspection (https://datatracker.ietf.org/doc/html/rfc7662)
*2: By applying Key Encryption defined by RFC 7516 and 7518, a token itself is encrypted by a shared key named Content Encryption 
Key (CEK) in symmetric algorithm and the CEK is encrypted by a public key named Key Encryption Key (KEK) and decrypted by its 
private key in asymmetric algorithm.

Token Types That Can Prevent Information Leaks
Handle/Reference type token:
• Pros: No information included.      No information leaked.
• Cons: Need token introspection.                    Response time increased.
• Cons: Cannot know who issue the token.      Cannot support multiple AS.  
Signed and Encrypted JWT-formatted Assertion/Self-contained type token:
• Pros: No need token introspection.                Response time not increased.
• Pros: Can know who issue the token.            Can support multiple AS.
• Cons: If decryption key is stolen                    Information leaked.
• Cons: Need decryption.                                  Response time increased.

Key Takeaways
• For secure cross-domain multi-hop API calls, forwarding an access token and 
token exchange only have some issues.
• Instead, OAuth Identity and Authorization Across Domains or MCP Elicitation in 
URL mode does not have such issues but has other potential issues.
• To resolve the issues, some additional security measures can be applied: using
session cookie, user ID comparison.
• However, whether the measures can be applied depends on the security of 
different domains. Therefore, the different domain’s security needs to be 
investigated in advance.
